# 解释动画库

解释动画只在一个地方出现：口播在描述一个**过程**（东西怎么流转、工具背后怎么跑、老办法要来回几遍），
而手里**没有素材能直接展示它**。是否需要、用哪个，按段判断（editing-logic.md B0）；一条视频里一个都不用也很正常。

选的时候看**这段话的形状**，不看话题：同一个组件可以讲剪辑，也可以讲客服、写代码、做报表。
库里没有形状合适的，就现做一个（见文末“怎么收进库”），不要硬套。

| 组件 | 这段话的形状 | 口播里常见的样子 | 横 / 竖 | 预览 |
|---|---|---|---|---|
| `retrieve` 检索匹配 | 一段输入 → 挑出关键 → 在一堆东西里找 → 命中的亮起；改了输入，命中跟着变 | “根据文案的关键词去搜素材”“改改关键词就能控制方向” | 横竖都自己排版 | [横](explainers/retrieve.jpg) · [竖](explainers/retrieve-portrait.jpg) |
| `pipeline` 流水线 | 一条条输入流进一个处理者，结果落到输出上各自对应的位置 | “把每一句文案交给智能体，自动配上画中画” | 横竖都自己排版 | [横](explainers/pipeline.jpg) · [竖](explainers/pipeline-portrait.jpg) |
| `roundtrip` 来回成本 | 一个小改动要绕完整个流程，每一圈都有代价（时间、额度）；新办法一条捷径横切过去 | “改一个小地方还得回去重新跑一遍”“既耗额度又白白等” → 后面“现在不用了” | 横竖都自己排版 | [竖](explainers/roundtrip.jpg) |

## 各组件

### `retrieve(start, script_title, script_lines, keywords, tiles, queries, outcome)`
- 文案里用 `[词]` 标出关键词，`keywords` 给每个词被说到的时间。
- `tiles` 是被搜索的那一堆东西，约 12 个效果最好；有真实画面就放 `tile(..., media=image/video)`。
- 第二条 `query` 换掉一个关键词（`changed`），演示“改输入，结果跟着变”。
- 动起来的是那几个词本身：被标出的关键词从文案里飞进搜索框、落下时变成搜索词（第一条 query 的 chips 与 keywords 按顺序对应）；
  换词时旧词被弹出掉下、新词逐字打进来；扫描光扫到哪排哪排就反应——命中的弹起、冒一圈光、打勾，其余变暗。
- 竖屏：文案在上 → 搜索框 → 三列素材格，镜头依次框住文案、文案+搜索框、搜索框+素材格、素材格+结论。
- 来源：20260915 MoneyPrinter，讲关键词搜索素材那段。

### `pipeline(start, input_title, engine, output_title, items, engine_at, output_at, outcome)`
- `items` 每一条输入在说到时流进处理者，再作为片段落到时间线的对应格子；片段可以是真实画面 `clip(..., media=...)`。
- 动起来的是那一句本身：轮到的那行整条脱离文案、滑进处理者（处理者咬一下、外圈转快），吐出片段卡飞进时间线上它的格子落定，原行打勾；
  全部落定后播放头扫过时间线，片段依次亮起。
- 竖屏：输入在上 → 处理者 → 时间线（排得紧凑）；镜头先框输入、输入+处理者，句子开始流动时框住整条路径（看得到句子离开和片段落位），最后时间线+结论。
- 来源：20260915 MoneyPrinter，讲造物智能体自动匹配画中画那段。

### `roundtrip(start, trigger, steps, meters, outcome, shortcut)`
- `trigger`：引起这一圈的那个小地方，最好是它的真实画面（`media=video(...)`）。
- `steps`：圈上的各站，每站在说到时点亮；要花时间的那一站加 `progress=True`（渲染、上传）。
  触发的那个小东西（`trigger.media` 的画面）会从卡片里飞出来，绕圈停靠在说到的那一站。`act` 决定这一站对它做什么：
  `"edit"` 在画面上划一笔，`"render"` 画面变灰后从上往下重新生成（`progress=True` 时默认用这个），`"wait"` 画面压暗并显示转圈。
  `drain` 计量条在往下掉时，额度会一枚枚掉出来。用了捷径时，会有一张绿框的副本沿绿线直接横穿过去。
- `meters`：每一圈的代价，`drain` 是往下掉的条（额度、配额），`count` 是往上走的计时（等待）。
- `shortcut`：新办法，(图标, 文字, 时间, 副标题)；它出现时绿线从小地方直接横切过去，旧循环变暗。
- 常见用法：讲痛点时画出循环；后面讲到好处时 `recall` 飞回这一站，让捷径横切（`ring_of(scene)` 给回访时只框住圈的取景）。
- 来源：20260923 编辑台（竖屏），20–26s 老办法的来回、71–76s 飞回横切。

## 怎么收进库（每条视频剪完时做一次）

剪完一条视频，如果这条里**现做**了解释动画，问一句：它讲的是一类会反复出现的过程，还是只属于这一句的特例？
是前者，就把它收进库：

1. **参数化**：内容（文字、图标、步骤、时间）全部变成参数，组件里不留这条视频的任何字。形状不变、换个话题也能用，才算通用。
2. **横竖都能排**：读 `vertical`（Python 侧用 `common.PORTRAIT`），竖屏把各部分上下叠放、字号放大，镜头只框住正在讲的那部分。
3. **同一套视觉**：玻璃表面（`surface()`）、`Label`、图标块（`iconTile()`）、暖琥珀强调、红色代价、绿色正向、弹簧动效；时间全部是绝对毫秒（`at`），由 `finalize` 换算。
4. **自带镜头路线**：生成函数返回 `_scene(...)`，镜头先看开头（输入 / 触发），再到过程，最后看全貌。
5. **登记**：TSX 放在运行时 `src/`（单独文件或 `explain.tsx`），在 `elements2.tsx` 的 `REG` 和 `types.ts` 注册；Python 生成函数放 `canvaslib/explainers.py` 并从 `__init__.py` 导出；改完运行时复制回 skill 的 `template/src/`。
6. **写进这张表**：形状、口播里常见的样子、横竖支持、来源视频，再存一张预览图到 `references/explainers/<名字>.jpg`（抽一帧关键画面）。

只用一次、换个话题就讲不通的，留在那条视频的节目脚本里，不进库——库里的每一个都应该是下次真会被选中的。
