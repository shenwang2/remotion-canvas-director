# 剪辑逻辑

## 出发点：观众此刻需要什么

一条口播里，观众会不断出现“没跟上”的瞬间：一个名字只听了一遍、一句“这里看一下”却看不到“这里”、
一个抽象说法想不出画面、说到“刚才那个”时已经忘了是哪个。前景的工作就是在这些瞬间接住观众，
接得准、接得及时，画面自然有质感；没有需要的地方就让人物自己说。

所以本 Skill 不从“有哪些组件可以用”出发，而是：
**逐句读口播 → 判断观众在这一句的理解需求 → 选一种回应 → 让回应跟着说话的节奏出现。**
议程清单、章节角标、回顾这类结构提示，只是“定位”需求的一种回应，不是每条视频的固定配置。

---

## A. 理解需求 → 前景回应

`scripts/annotate_needs.py` 先按字面线索给每句打上候选需求（`analysis/needs.json`）。
这只是起点：字面线索会漏（“破万”、“印钞机”这种昵称）也会误报（“下期再见”的“再”），要带着整条口播的意思复核。

| 需求 | 观众的状态 | 常见口播线索 | 可选回应 |
|---|---|---|---|
| remember 记住 | 名字、数字只听一遍会丢 | 产品名、数字、英文术语、昵称 | 名字/数字上屏：大字、数字卡、素材卡标签、截图高亮 |
| point 指认 | 听到“这里/这个”却看不到 | 这里、看一下、你看、就是这个 | 那个东西在这个词上出现：录屏、截图并框出、成品全屏 |
| orient 定位 | 不知道讲到哪、接下来讲什么 | 换话题、列举、预告、“第一个…”、“以上就是…” | 小节标题卡、跟着说出来逐条冒出的清单、进度角标、回顾；话题自然转换时一个标题卡就够 |
| relate 关系 | 几样东西怎么连 | 先…再、因为…所以、不是…而是、对比 | 对应的画布排法（B 节） |
| concrete 具象 | 抽象说法想不出样子 | “XX 的能力”、“自动化”、“效果很好” | 用素材或示意把它演一遍 |
| callback 回指 | 说“刚才/前面/它的那个”时已忘了是哪个 | 刚才、前面、之前、将其、这个能力 | 镜头飞回地图上那一站并重新点亮（`look_back` / `recall`） |
| attitude 态度 | 他的判断是要点 | 最骚、我靠、绝对、一定要、讲实话 | 推近人物，同时把这个判断作为强调落下来（标签、贴在相关画面上的“印章”） |
| wrap 收束 | 需要把前面串起来 | 以上、总之、所以说 | 镜头拉远看整张地图，或逐条回顾 |
| （无） | 这句不是要点 | 口头过渡、语气词 | 不强调；镜头和节奏照常走 |

举一反三：需求是从观众角度判断的，同一句话可能同时有几种（“看人家的 star 数有 124k”= 指认 + 记住）；
没有字面线索也可能有需求（突然换话题却没说“接下来”）。表里的回应也不是唯一答案，按这条视频的素材和节奏选。

## A2. 前景是什么

字幕和前景是两个通道：字幕把每一句交代清楚；前景把**值得观众记住、理解的要点**挑出来，
用设计、动效和时机强调它、留住它。前景用他的原话完全正当——同一句话被设计成卡片、在说到的那一刻
跳出来、和其他要点排在一起，本身就在加强记忆和理解。

所以判断只有一个：**这一点值不值得观众记住或理解？** 值得，就用最合适的形式强调出来；不是要点
（口头过渡、语气词）就不强调。形式按内容挑：

- 要点、判断、承诺 → 在人身旁或相关画面上落下卡片 / 标签（`presenter(..., beside=[[...]])`、贴在素材上的标签）。
- 一组并列的要点 → 逐条出现、留在一起，让观众看到“有这几点”。
- “长什么样”说不清 → 演示或对比（`before_after`），比文字更直接。
- 一句话引出明显的问题（“找我聊聊”→怎么找） → 前景顺手把答案给出来。
- 情绪最强的那句 → 推近人物，可以和强调同时用。

人物镜头里的卡片位置按人脸自动算（横屏在侧面；竖屏优先在头顶上方的墙面，放不下才在下巴下方），话题换了整组换；大字出现时卡片让位。

## A2b. 人物镜头：一行一张小卡片，只有小画面才用大卡片

人物身后的房间通常很杂（显示器、灯条、窗帘）。前景用 visionOS 式的水晶玻璃，把背后柔化成安静的表面，
文字永远落在玻璃上、不裸露在画面上。

**默认载体是一行一张的小卡片**，不是一块大面板：
- 一个要点 → 一条 `tag`：左对齐的胶囊，字从左往右读，宽度跟着字走（`_layout_beside` 量字数定宽，`STRIP_H` 定高）。
  同一段的几条放在同一组里（`beside=[[tag(...), tag(...)], ...]`），说到哪条冒哪条，排成一列。
- 章节点、一段的结论、概念名 → 一张带图标的 `card`（标题 + 一行小字），同样按字定宽。
- 只有一个点（一句悬念、下期预告、我是谁）→ 一张卡片或一个强调大字。
- 要贴在某个东西上的（对成片下的判断）→ 直接贴在那个东西上（`stamp` 等）。
- **要演一个小画面时才用大卡片**：`glass(state(..., kicker, title, visual=...))`——小号说明 + 一行大标题 + 小画面，一张大卡片只装这一段。
  不要把一整段话的几个状态塞进同一块面板：面板按最高的那个状态撑高，字少的时候空着一大块，竖屏还会被挤到头顶、糊住头发。

为什么这样定（用户在 2026-11-01 那条里对比后定的）：一块大面板“不管字多字少都是一个很高的大卡片”，空间被白占、人像头部也不好看；
拆成一行行的小卡片，高度只跟内容走，观众一行一行读。

**位置**：竖屏优先放在头顶上方的墙面（画面高度 10%，即左上角章节标下面，到头顶），贴着这块区域的**上沿**、左对齐，离头越远越好；
一组放不下才回到下巴和字幕之间。左上角章节标已经写了的（“02 人物画面”），不要再放一张同样内容的卡片——既重复，又把一组撑高到放不下。

**配色**（实拍专用 `VTONE`，elements1.tsx）：字是白的，颜色只落在图标的圆底和 `{关键词}` 上，一张卡一种颜色；人物实拍上**不用黄色/琥珀**（暖光房间里发脏）。
颜色跟着意思走：以前 / 问题 / 代价 → `red`（珊瑚红）；现在 / 好的变化 → `green`（薄荷绿）；信息、结论、操作 → `cyan`（天蓝）；
章节、概念名 → `purple`（淡紫）；一般要点 → `accent`（雾蓝）；品牌 → `orange`（珊瑚橙，少用）。
写法：`tag("以前：一块玻璃，{几行字}", "red", at, icon="History")`、`card("Workflow", "{解释型}动画", "03 · 我觉得最有意思的", at, tone="purple")`。

大卡片内部的版式：小号 kicker → 大号标题（`{词}` 强调）→ 小画面（见 A2d）；也可以是副标题、行列表、底部胶囊（可划掉）、揭晓用 `hero` 大字。
材质：人物镜头上默认 crystal（通透），背景特别亮、小字读不清时换 glass（磨砂更重）。

例（2026-11-01 开源那条，不是模板）：开头 “这条视频 · {AI 自己剪的}” 一条；“怎么获取 · {视频最后讲}” “这次 skill {改了什么}” 两条一组；
“以前：一块玻璃，{几行字}” 红 / “现在：先看这句话的{形状}” 绿；“旧版被淘汰”“只给一个框架” 两处要演小画面 → 各一张大卡片；“{一键三连}” 卡片 + “进我主页的{公开群}” 一条。

## A2c. 人物镜头的景别变化（剪辑感）

景别变化像说话里的重音和标点：用得少，每一下才有分量；切得频繁，画面就烦杂、没有重点。所以留给真正值得的时刻：
- **一段话里最重的那一下**：最关键的揭晓、最强的情绪、最重要的号召。很多段一次都不需要。
- **论证的大转折**：明显进入下一部分时，换一档景别帮观众感到“翻页了”。
- 人物镜头和画布本来就在交替，节奏已经有了；只有人物镜头持续很久、画面一直不变时，才考虑换一次景别提神。

切近之后不急着切回，停在近景，等下一个自然的转折再回远景（少切一次）。所有变化以人脸为中心，人脸位置不动，玻璃元素不受影响。
放大有上限（约 1.35 倍以内），再大画面会发虚。

手法（`presenter(..., zoom=[...])`）：
- `snap(at)` 快速推近（约 0.16 秒，带一点运动模糊）——揭晓。
- `punch(at)` 冲击切近（一帧切过去，落定时轻微回弹）——最重的一拍。
- `back(at)` 切回——下一部分开始。
- `push(at, scale, ms)` 慢推——情绪在几秒里往上走，可以推到高潮再接一个 `punch`。

本片（141 秒）只用了三次：“印钞机” snap 并停在近景直到切进画布；“越来越好” punch 并停在近景说完号召；“后续呢” back。
检查会在两次景别变化挨得太近、或 30 秒内变化太多时提醒回头看一眼——这是提醒，不是配额。

## A2d. 面板里的小画面：把意思演出来

画布那边有地图、动画、素材；人物镜头这边如果只剩一块写着字的玻璃，两边的水准就差一截。面板是容器，
容器里的内容也要跟着意思走：一句话的“形状”是替换、流程、程度、选择题时，文字只能描述它，一个小画面能让观众一眼看到它。
所以可以用一张大卡片（`glass(state(..., visual=...))`）在标题下面带**一个**小画面，同一套玻璃质感、弹簧动效。
一张大卡片只装一个这样的状态（一段话一张），不和别的要点共用一块面板（A2b）。

按这句话的形状挑，不按话题挑（同一个形状可以讲剪辑，也可以讲写代码、做报表）：

| 这句话的形状 | 小画面 | 例子（20261024 那条） |
|---|---|---|
| 旧的被新的替换 | `vis_swap(old, new, swap_at)`：旧的盖章变暗，新的滑进来 | “用 Opus 5.5 重写，旧版直接被我淘汰了” |
| 讲画面本身怎么拍、怎么切 | `vis_phone(beats, labels)`：迷你手机里人物全屏 / 配卡片 / 推近 / 缩成头像进画布 | “只有两种镜头”“配一些卡片，情绪到了推近” |
| 一个做法被推翻、换成另一个 | `vis_flow(flow_row([...], strike_at), flow_row([...]))`：一排步骤被划掉，下一排是新做法 | “不再先分场景再找组件，而是一句一句琢磨会不会卡住” |
| 多少、一样、差了多少 | `vis_bars([bar(...)], note)`：几根条一起长；`ghost` 虚线表示本该到的水平 | “原样拿过去效果差不多，这不应该是它的水平” |
| 只给个架子，其余由别人填 | `vis_frame(at, fill_at, label, fill_label)`：空框架被一格格填满 | “只给大体框架，其余让它自己发挥” |
| 让观众选 | `vis_poll([("A", ...), ("B", ...)], hint_at)`：两个选项卡，提醒评论区站队 | “你更想要一键出片，还是剪完自己再改” |
| 一个判断、一种态度 | `vis_stamp(text, at)`：印章砸在玻璃上，可以和景别冲击切近一起用 | “主要还是 Opus 5.5，实在是太强了” |

库里没有合适形状时，可以在 `glassvis.tsx` 里按同一套质感现做一个，用过觉得会反复出现就留下。

边界（不然会退回旧版“一句配一个组件”）：
- **只在小画面让观众更快懂、更记得住时用。** 一句只有一个点的话（“核心制作思路”、署名），一张卡片或标题就是对的。
- **一个状态只放一个小画面，标题保持一行。** 竖屏头顶上方只有约 450px，人物才是主角；`finalize` 在放不下时会提示。
- **相邻的面板别连着用同一种**，跟着内容变。
- **小画面里只演他说出来的东西。** 对比条的长短只表达“一样 / 更多 / 差一截”，不编数字；投票卡不放假的票数。
- **小画面比文字更怕说得快。** 印章、虚线、答案那一下要停得住：带小画面的状态至少约 1.8 秒，最后一下出现后至少约 1.2 秒才切走。
  说得快的地方，把下一状态推迟到下一个意群（例：“太强了”之后马上接“我之前在 Codex…”，就把下一状态推到“经过好多条”），
  或把这一下并进前一个状态（例：“这不应该是它的水平”只有 1.3 秒，就把虚线并进“效果差不多”那个状态）。`check_program.py` 会查这两条。

## A2e. 身后大字：关键词立在人物身后的房间里

把一个词放在实拍画面和抠出来的人物之间：字立在墙上，头发轻轻挡住字的下沿，看起来是房间里真的有这几个字。
它好看是因为合成得真，不是因为特效，所以字上不加扫光、粒子、发光，就是干净的大字。

**什么时候用**：揭晓的那一刻，比如这条视频做出来的东西叫什么、整条在讲的核心概念。“所以我给全自动剪辑做了一个——编辑台”就是这种时刻。
它是招牌镜头，一条视频一两次；一般的强调用玻璃面板的 hero 大字或 `bigWord`。

**写法**：`presenter(..., behind=[behind_word("编辑台", at, end)])`。
- `at` 是说出这个词的时刻（`word_at(...) + 300` 左右，词说出来字再立起来），`end` 一般到这个人物镜头结束。
- 抠像由 `finalize` 第一次运行时自动做（只抠 `at` 前 0.4 秒到 `end`，约每秒画面 18 秒，用 GPU），存成 `public/media/matte_<at>.webm`，之后直接复用；改了时间要删掉旧的让它重做。
- 位置和字号自动算：从抠像里量出这段时间头顶最高的位置，让头只盖住字的下沿 30%；字号受头顶空间、画面宽度和这一刻的放大倍数限制。
- 字只用 2–4 个字的那个名字本身，副标题（`sub`）只在头顶空间很大时加。

**限制**：
- 字立着的时候画面不动：这段时间不放景别变化（推近会把头顶上方的字推出画面），这一刻的分量交给字本身。
- 头顶空间太小（近景、头顶贴着画面上沿）时字会很小，`finalize` 会提示：换个时刻，或改用玻璃面板。
  录制时头顶多留一点空间、人和背景墙之间有点距离，这个效果最好。
- 人物镜头里同一刻的玻璃面板会自动让开；面板别和大字讲同一个词，面板铺垫（“所以我给…做了一个——”），大字揭晓。

## A3. 形式跟着意思走

同样是“强调一个要点”，怎么出现本身就在表达意思。先想清楚这句话的意思是什么，再挑最能把这个意思
“演”出来的形式；不要所有东西都是一张卡片淡入。下面是现有的形式和它们擅长表达的意思——是词汇，不是对照表：
一句话可以有别的更好的演法，也可以组合，或者在没有合适形式时新做一个（motion.tsx）。

| 形式 | 擅长表达 | 本片里的用法 |
|---|---|---|
| `stamp` 印章砸下 | 定论、判断、认证 | “完全已经够用了”盖在直接生成的成片上；“不是无人区的老项目” |
| `rise` 上升线 | 变好、增长、潜力 | “会变得越来越好”；“落地性和潜力都很高” |
| `multiply` 一个复制成一群 | 批量、数量、规模 | “设置同时生成视频的数量” |
| `scan` 光带扫过、命中点亮 | 搜索、匹配、识别 | “自动匹配网络上的画中画素材” |
| `erode` 红色脉冲、字被削弱 | 正在流失的窗口、风险 | “趁信息差还没被削弱”里的“信息差” |
| `strike` 划掉、打叉 | 否定一个说法、纠正误解 | “可不是啥标题党” |
| `marker` 荧光笔划过 | 一个必须记住的词 | 开头“一定要看” |
| `circle` 聚焦框 | 在真实画面上指出一处（规整圆角框，不手绘） | 关键词那一栏、star 数 |
| `highlight` 聚光框 | 让观众只看截图里的这一块 | 同时生成数量、仍在更新的提交 |
| `stat` 数字滚动 | 数量本身就是说服力 | 点赞破万、124k |
| `before_after` / `compare` | 差别、取舍 | 直接生成 vs 精修后 |
| `card` / `tag` | 一般的要点、并列的几点 | 客户想法驱动优化、加新功能 |
| 镜头（推近/拉远/飞回） | 情绪、揭示、回指 | “我靠”推近；飞回关键词那一站 |

`card` 的入场也按位置和关系选（`enter`: slideL/slideR/flip/pop）：人身旁的卡片从它靠着的那一边滑入。
同一个意思连着出现时换强度或换形式，让观众每次都感到“这次不一样”，而不是在等下一张卡片。
预设排好的元素可以用 `restyle(scene, id, kind, ...)` 换成更贴切的形式。

## A4. 质感统一

整套画面是规整、精致的玻璃版式，标注和动效要和它是同一种做工：
- **不要手绘感**：圈画重点用规整的圆角聚焦框（`FocusRing`，平滑描出、带柔光、贴合目标），不用抖动的手绘线。
- **歪斜、弹跳、抖动这类动作是可以的**（印章歪着砸下、标签带一点角度），它们是动作的表达，不是做工粗糙。
- **标签统一用玻璃胶囊**（`Label`：深色玻璃 + 彩色小圆点或图标）；描边统一偏细，配同色柔光，不用粗实色框。
- 画布卡片默认玻璃款（`canvasStyle: "glass"`），右下角头像是玻璃镜框；人物镜头上的面板是水晶款。

## B0. 素材优先，解释动画补位

画布上讲一件事，先看手里有什么：
1. **有真实素材，先用真实素材**——录屏、截图、成品、数据截图。它们本身就是证据（观众信“这是真的”），信息量也比示意图大。
   用来回答“是什么、在哪里、效果如何”。
2. **素材展示不了的，补一段解释动画**——工具内部怎么运作、为什么会这样，这些在录屏里本来就看不见。
   常见做法是两者接着用：截图讲“设置在哪”，动画讲“背后怎么运作”。动画里的格子、片段尽量用真实素材的画面（`tile(..., media=image/video)`）。
3. **完全没有素材的抽象内容**，才用纯图形的解释动画。

这个判断**按段做，不按整条视频做**：一条视频录屏再多，也可能有一段在用嘴描述一个没人录下来的过程（老办法要来回改几遍、工具背后怎么跑、东西怎么流转）。`annotate_needs.py` 会列出这类段落，`check_program.py` 会在它们只有人物加文字时提醒；但列表只是线索，自己通读口播时发现的过程同样要问一次。

解释动画的来源：
- **组件库**：`references/explainer-library.md` 列着库里每个组件讲的是哪种形状的过程、口播里常见的样子、横竖屏支持和预览图。
  按这段话的形状挑，不按话题挑；内容、关键词、每一步的时间都是参数。
- **临时现做**：库里没有形状合适的，就针对这段写一个专属组件，遵守同一套视觉规范
  （玻璃表面、`Label`、`FocusRing`、细描边、暖琥珀强调、弹簧动效、镜头跟着讲述推进）。
  剪完后按 explainer-library.md 文末的步骤判断要不要收进库——库是一条条视频剪出来、慢慢长大的。
- 解释动画的镜头要跟着讲述走：先推近输入，再移到处理，最后拉远看全貌（组件自带这条镜头路线）。

### B0b. 解释动画要像动画，不像一张会亮的图

只让框一个个亮起来，观众看到的是一张示意图。像动画，是因为**过程里的那个东西真的在动、在被处理**：
1. **物体连续**：被处理的东西从它出现的地方出发，一路走完整个过程，不换成光点、箭头这些替身。
   例：`roundtrip` 里那段视频的画面本身从卡片里出来，绕完一整圈。
2. **每一站对它做点什么**：说到哪一步，它就在那一步被改、被重新生成、被搁着等（`step(..., act=...)`），
   观众看到的是这一步的后果，而不是这一步的名字。
3. **代价看得见**：消耗的东西真的掉出去（额度一枚枚掉落），等待真的在走。
4. **运动有分量**：移动时带一点拖影、顺着方向微倾，落下时站点轻轻一沉再回弹。这些幅度都很小，让人感觉它有重量，但不会注意到它。

这里的“特效”都是过程本身的画面，不是装饰：扫光、粒子、发光这类和那句话没关系的东西不加。
**平面还是纵深**：默认平面。动画感靠物体连续、因果和分量，不靠透视；讲信息、步骤、逻辑的过程都用平面（检索已对比确认：平面）。
只有讲的东西本身有前后层次或空间结构（图层前后拆开、一个真实物体要转过来看、空间里的布局）——拿实物讲时要“转一转、拆开”才说得清——才值得纵深（2.5D，不做真 3D）。
这类内容**第一次**出现时：成片照常用平面做完交付，另渲一版那一段的纵深对比随成片附上，不停下来等用户；用户选了就记在下面，同类以后直接沿用。
已定：检索（从一堆里挑出来）→ 平面。

### B0c. 特效候选：从口播里的“动作”来

特效值得用的时刻，往往是口播里有一个**动作或变化**，画面本身表达不出来，比如“彻底推翻”、“全都汇到一起”、“一下省掉这一大段”、“越堆越多”。
写节目脚本时把这样的时刻挑出来，作为**特效候选**列给用户：时间、原话、打算怎么动、为什么，由用户决定用不用。
不预先做特效库，也不默认加特效。用户选中的做出来后，按 explainer-library.md 的步骤收进库，用户的特效语言就是这样一条条攒出来的。
做得到就在 Remotion 里做；需要真 3D、粒子模拟这类 Remotion 做不好的效果，才去 AE 渲染成透明视频再放进来。

## B. 关系 → 画布排法（工具箱，不是模板）

| 内容关系 | 预设（scripts/canvaslib） | 说明 |
|---|---|---|
| 有操作录屏的步骤 | `demo_steps` | 录屏在说“看一下”时出现；每一步在说到时出现并点亮 |
| 示例 + 数据 + 分类 | `example_stat_kinds` | 示例 + 大数字 + 类别卡 |
| 某个设置 → 能带来什么 | `shot_focus` | 截图高亮推近 → 结果卡片带箭头 |
| 某个设置 → 后续玩法 | `shot_then_timeline` | 截图高亮推近 → 平移到时间轴 → 警示 |
| 证明可靠 | `evidence_wall` | 截图上逐个框事实 + 数字滚动 + 判断标签 + 第二份证据 |
| 并列的几样东西 | `feature_cards` | 标题 + 一组卡片 |
| A 导致 B 导致 C | `cause_chain` | 卡片依次出现，箭头依次画出 |
| 两种方案/前后对比 | `compare` | 两列清单 + 结论标签 |
| 某样东西“改进后长什么样” | `before_after` | 原样与改进后的真实画面并排，改进点在说到时出现 |
| 回到前面讲过的东西 | `recall` / `look_back` | 镜头飞回那一站，旧元素重新点亮 |
| 一个看不见的过程（检索、匹配、处理） | `retrieve` / `pipeline` | 解释动画，见 B0 |
| 老办法的来回代价 / 新办法省掉了什么 | `roundtrip`（+ `shortcut`） | 解释动画，见 B0 |
| 先立后破、比例规模、地点分布… | 自造 | 用同样的元件拼，取新的 `layout` 名 |

卡片上的字是口播的压缩，用他的说法（“不是无人区的老项目”），不复述整句字幕，也不写口播里没有的总结。

## C. 记忆地图

同一条视频的画布镜头默认放在同一张地图上（`canvas(..., world="main")`，横屏向右、竖屏向下依次铺开）。
讲过的东西留在原地；回到画布时镜头从上次离开的位置飞过去，而不是硬切。
这让观众感到前后是连着的，也让“回指”有了最自然的回应：飞回去、点亮它。

回到一站讲**新的点**时（例：先在编辑台全貌上标“左边是素材”，后面又回来讲“右上角的导出”），
新的指示要单独出现：上一轮的框、标签、“点这里”之类的指示用 `retire(scene, ids, at)` 在那一轮讲完时退场，
截图、录屏、卡片这些内容本身留着。新指示直接加在那一站的元素里（时间写它被说到的时刻），镜头用 `focus` 对准它——
镜头停点的 `rect` 是地图坐标，排进地图之后会偏，所以对准元素而不是手写区域。

竖屏的各站沿页面向下排，取景区只到屏幕 60% 高度，下面一截会透出地图的其余部分；所以竖屏站距更大（`GAP_PORT`），
取景区以下自动渐隐压暗，字幕和头像下面不会和别的站抢眼。

## D. 跟着说话呼吸（质感）

- 画面比关键词早约 150ms 出现（`word_at` 默认已减去），观众会觉得画面是“跟着”剪的。
- 重音和落点：数字落定、判断标签出现时有一道扫光和音效；态度最强的那句推近人物。
- 停顿时不加新东西，让观众消化；截图的“聚光灯”压暗只持续一瞬，过后只留框。
- 镜头路线跟着论证走：先全景再钻细节（先结论后证据）、先细节再拉远揭示、横向一路走过去（流程）、两处来回（对比）。

## E. 底线（`check_program.py` 自动检查）

- **ERROR**：镜头 < 1.5s；大字 > 5；相邻画布同一种排法；用了 hud 结构提示却没有内容。
- **WARN，双向核对**：
  - 前景元素的文字和它出现前后几秒的口播对不上 → 可能是装饰或编出来的总结（跟素材一起出现的标题算素材说明，不在此列）。
  - needs.json 里的名字/数字没在屏幕上出现、“看一下”时画面还是人物、回指时没有飞回去、一段过程描述只有人物加文字 → 可能漏了。
- **WARN，可读与节奏**：文字太小、停留太短（画布元素按它真正被看到的那个镜头算；人物镜头里的卡片和面板的每个状态也算——
  揭晓刚出来就切走是最常见的情况，推迟切走或提前这一状态；带小画面的状态要停更久，小画面里最后一下出现后也要停住，见 A2d）、
  镜头运动单一、镜头时长太均匀、人物占比偏离 30–60%、身后大字超过两次或底下有景别变化（A2e）。
- 生成时（`finalize`）还会提示：竖屏人物下方放不下的玻璃面板（内容会被裁掉，状态写紧凑些：一行标题 + 胶囊，或 hero 大字）；身后大字头顶空间不够、抠像没覆盖它的整段时间。
- WARN 要么改，要么在 `brief.exceptions` 里写明这条为什么例外。

## F. 出片前自检（抽帧看，图不给用户看）

逐屏问：这一屏在接住观众的哪个需求？一眼能看懂吗？跟上一屏是不是一个样子？截图重点看得清吗？招牌时刻是不是全片最好看的一屏？

## G. 背景音乐与卡点（`finalize(..., music=music(...))`，canvaslib/bgm.py）

说的话仍然是时间线，音乐是叠在下面的第二个时钟：它给整条视频一个情绪起伏，并让画面的动作对得更齐。
音乐不决定画面在哪一刻出现，那仍然由说到的词决定；它只把附近的动作挪到拍子上。

**曲库**：用户自己的曲子，放在 `$CANVAS_MUSIC_ROOT`（默认 `~/canvas-director-music`），按情绪分文件夹。skill 不带音乐。新放进曲子后跑一次
`python scripts/analyze_music.py <曲库目录>`，
它生成 `catalog.json`（节拍、重拍、段落、能量、起势点、响度）和给人看的 `曲库说明.md`。

**选曲**：用户按听感选定的曲子写在 `曲库/偏好.json` 的 `default`，`music()` 不写参数就用它。
曲子单听判断不了，放进视频里才知道搭不搭：要换曲时跑 `scripts/music_sampler.py <work> --from 秒 --to 秒`，
同一段画面依次配上曲库每一首，让用户按编号挑，选中的写回 `偏好.json`。
不要凭节奏感、能量这些数据替用户选：试过“节奏感弱的平淡”“节奏感强的太吵、不搭”，数据只能用来摆放和卡点。
只有用户没定过默认曲、又给了情绪（`music(mood="科技感")`）时，才按数据在那个文件夹里挑一首，并出试配样片让用户确认。

**自动做的三件事**：
1. **摆放**：曲子有明显起势点（音乐抬起来的重拍）时，把最强、又放得下的那个对到这条视频的揭晓时刻
   （默认是第一个身后大字，其次是第一个 `bigWord`，也可以 `music(..., hit_at=毫秒)` 指定）；没有起势点就从曲子开头放。曲子不够长时在重拍上循环。
2. **音乐有形状，不是一条直线**（只靠停顿抬音量不够：去过停顿的口播几乎没有 0.6 秒以上的停顿，用户听到的就是“响度一直统一”）：
   开头钩子音乐放出来（+5 dB），说话时压在人声下面（偏好里的档位，现在低约 14 dB），画布讲解时再低一点，
   每个踩在拍子上的转场音乐涌上来（+7 dB）再在 1.5 秒里落回去，揭晓前 0.65 秒音乐骤停、揭晓时砸回来，结尾那段话抬起来，最后 2.5 秒淡出。
3. **卡点要让人感觉到**（只把切换挪到拍子上看不出来：人物和画布之间是半秒的变形，没有“咚”的那一下）：
   - 让转场**落地**的那一刻踩在拍子上（人物⇄画布的变形结束、画布镜头飞到第一站），开头、章节、结尾踩重拍。
   - 每个落地点是一个**重音**：画面轻轻一推、微微一亮，三分之一秒内回去（Main.tsx），同时音乐涌上来。景别变化也算轻的重音。
   - 卡片、标签弹得最高的那一下踩在拍子上；镜头移动时长取整到半拍，并在拍子上到达。
   - 字幕、说话本身、揭晓那一刻不动。
   音效跟着卡点后的时间生成，所以也落在拍子上。

**可逆**：`finalize` 同时写出 `program.nomusic.json`，那是没有音乐、什么都没挪过的同一个节目，
想在剪映里自己加音乐就渲染它。`CANVAS_NO_MUSIC=1` 运行节目脚本则完全跳过配乐。

**检查**：起势有没有落在揭晓上、有没有地方被推到满音量（曲子太轻），汇总里报告用了哪首、卡点挪了几处。

**现状与迭代**：这一版（2026-10-29）用户认可为起点，等剪的视频多了再按听感慢慢调。
调的时候一层一层改（基础音量、转场涌起、揭晓骤停、画面重音），每次出改前改后的对比样片让用户凭感觉判断，不让他凭描述拍板。
